# Каталог и поиск в интернете

В каталоге 42 тестовых товара: 12 позиций бытовой техники, 10 продуктов питания, 10 стройматериалов, 9 IT-товаров и 1 смартфон в разделе аксессуаров. При старте существующая SQLite-база дополняется недостающими позициями; сохранённые заказы, реальные цены и ранее найденные товары не перезаписываются. Тестовые цены отмечены как Demo и не являются реальными предложениями. Для просмотра всех позиций выберите «Barchasi».

## Включение

Скопируйте `.env.example` в `.env` и заполните:

```dotenv
OPENAI_API_KEY=ваш_секретный_ключ
OPENAI_MODEL=идентификатор_модели_для_структурированного_ответа
OPENAI_SEARCH_MODEL=идентификатор_модели_с_поддержкой_web_search
ONLINE_SEARCH_ENABLED=true
ONLINE_SEARCH_DAILY_LIMIT=100
ONLINE_SEARCH_BACKGROUND_BATCH=10
```

Запустите `npm start` и откройте http://127.0.0.1:3000. Отдельный API поставщика для интернет-поиска не обязателен. Фиды поставщиков по-прежнему можно подключить независимо через `PRODUCT_SOURCES_FILE`.

`GET /api/search/status` показывает, включён ли поиск, количество использованных запросов за текущие UTC-сутки и результат последнего обращения. `configured=true` означает наличие настроек, а не успешную проверку ключа. Нужны доступная аккаунту модель, поддержка инструментов и средства для API-запросов. По умолчанию интернет-поиск выключен; без ключа его нельзя реально выполнить.

Используется [OpenAI Responses API с Web Search](https://developers.openai.com/api/docs/guides/tools-web-search): обязательный интернет-поиск с live access, затем отдельное извлечение структурированных записей из отчёта. Это два API-запроса на одно исследование, плюс расходы на поисковый инструмент. Ключ и запросы к провайдеру остаются на сервере.

## Поиск на сайте

Сначала проверяется локальный каталог, включая сохранённые результаты предыдущих поисков. Если совпадений нет, через 1 секунду после прекращения ввода (от 3 символов) запускается интернет-поиск. Кнопка поиска и Enter запускают его без ожидания. Результаты появляются в подсказках и каталоге; явный поиск открывает сравнение первого подходящего товара. Изменённый во время ожидания запрос не заменяется результатом старого поиска.

`POST /api/search` принимает JSON `{"query":"название модели"}` (2–160 символов), отвечает `{products, source}`. Источник — `local`, `cache` или `internet`. Повторные параллельные запросы объединяются. Пустой результат кэшируется на час; ошибки провайдера — на минуту. При отсутствии настроек ответ 503 с объяснением, при исчерпании бюджета — 429. Есть ограничение 12 запросов в минуту на IP и не более двух одновременных исследований в процессе.

## Что сохраняется

SQLite содержит найденные карточки, поставщиков, точные цены UZS, тип цены (опт/розница/неизвестно), единицу и упаковку, минимальный заказ, подтверждённые способы оплаты, ссылки на цену и условия оплаты, время проверки и историю. Совпадения по URL и точной модели/единице помогают избегать дублей и смешения разных упаковок. Карточки с подтверждённым перечислением и соответствующие поставщики идут первыми, даже если цена выше.

Результат принимается только с HTTPS-ссылкой из использованных поисковых источников и подтверждающим цену фрагментом отчёта. Неизвестная цена, неподтверждённое наличие, рассрочка вместо полной цены и приблизительные цены исключаются. Оплата картой не приравнивается к перечислению. Без подтверждающего фрагмента и ссылки того же продавца способы оплаты остаются неизвестными. Ссылки видимы и открываются из карточки предложения.

ИИ анализирует найденные страницы, но это не гарантия актуальности продавца: поисковый индекс и сами страницы могут отставать. Время проверки означает время успешного поиска, а не дату обновления сайта поставщика. Перед покупкой проверяйте цену и условия по ссылке. Отсутствие предложения в новом поиске не доказывает снятие с продажи: старое предложение сохраняется, его время проверки не меняется и оно становится устаревшим.

## Фоновые обновления

При запуске сервера и затем каждый час обрабатывается очередь товаров и пользовательских запросов из SQLite. Каждый успешный поиск может добавлять новых поставщиков и новые модели в каталог. Очередь хранится между перезапусками и обходит сначала ещё не проверенные, затем самые давно проверенные запросы. Сайт получает обновлённый каталог раз в минуту.

По умолчанию за цикл обрабатываются 10 запросов, общий лимит — 100 исследований в UTC-сутки, включая пользовательские поиски. Поэтому **не каждый товар гарантированно перепроверяется каждый час**. Для полного почасового обхода увеличьте `ONLINE_SEARCH_BACKGROUND_BATCH` до размера очереди (максимум 100) и дневной лимит до соответствующего объёма с учётом стоимости. При 42 запросах полный почасовой обход требует до 1008 исследований в сутки, а добавление новых моделей увеличивает очередь. При исчерпании лимита прежние данные сохраняются; продолжение — в следующем цикле после сброса дневного счётчика.

Для постоянной работы сервер должен оставаться запущенным. Без работающего процесса и подключения к интернету фоновых обновлений нет. Проверки проекта: `npm test`. Интернет-адаптер проверен с тестовыми ответами; реальный вызов требует ваших настроек.
