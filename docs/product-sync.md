# Обновление товаров и проверка ИИ

Данные сохраняются локально в `data/bazzar.sqlite`, включая предложения, способы оплаты, историю цен и результаты синхронизации. При старте сервера запускается проверка, затем — каждый час. Сервер должен продолжать работать: закрытый процесс не обновляет данные. После перезапуска сохранённые данные остаются на месте.

## Подключение

1. Скопируйте `.env.example` в `.env`.
2. Скопируйте `sources.example.json` в `sources.local.json`. Замените пример адресом реального HTTPS JSON API поставщика. При отсутствии авторизации удалите `tokenEnv`; иначе запишите токен в соответствующую переменную `.env`.
3. Укажите в `.env` `PRODUCT_SOURCES_FILE=sources.local.json`, `OPENAI_API_KEY` и `OPENAI_MODEL` — идентификатор доступной вашему аккаунту модели с поддержкой Responses API и Structured Outputs. Ключ хранится только на сервере.
4. Запустите `npm start` и откройте сайт через `http://127.0.0.1:3000`.
5. Проверьте `http://127.0.0.1:3000/api/sync/status`: `state=ready`, `aiConfigured=true`, `sources[].lastRun.status=ok` означают, что настройки присутствуют и последний цикл прошёл успешно. `ready` сам по себе не подтверждает работоспособность ключа; смотрите `lastRun` и `pendingReviews`.

Без источника обновление через фид выключено. Без ключа или модели новые данные фида не публикуются (`ai_not_configured`). Пример конфигурации не является реальным магазином. Независимый поиск товаров в интернете теперь поддерживается: см. [online-search.md](online-search.md).

## Формат полного снимка поставщика

```json
{
  "products": [
    {
      "productId": "dazmol",
      "price": 350000,
      "currency": "UZS",
      "available": true,
      "paymentMethods": ["bank_transfer", "cash"],
      "description": "Philips DST3010, 2000W. Оплата наличными или перечислением на расчётный счёт.",
      "url": "https://supplier.example/products/philips-dst3010"
    }
  ]
}
```

`productId` должен точно соответствовать существующему товару в `/api/products`. Это явное сопоставление, чтобы ИИ не объединял похожие модели. Новые товары создаются через интернет-поиск или администратором; сам фид ожидает готовые ID. В пределах одного источника допускается одно предложение на товар. Цена — положительное целое число UZS за ту же единицу товара, что в каталоге. Адаптер источника должен приводить упаковки и единицы к каталожным до передачи фида.

`paymentMethods`: `bank_transfer` — перечисление на расчётный счёт, `cash` — наличные, `card` — карта. Отсутствие поля или пустой массив означает «неизвестно». Карта сама по себе не считается перечислением. Способ оплаты должен быть подтверждён данными поставщика; ИИ не присваивает его по названию компании.

Фид — **полный снимок**, не отдельная страница и не набор изменений. Отсутствующие в успешном снимке предложения этого поставщика снимаются с продажи. Пустой массив снимает все предложения поставщика. Невалидный ответ или ошибка HTTP не меняют предыдущие предложения. Перед подключением пагинированного API нужен адаптер, собирающий все страницы в один снимок.

## Проверка и публикация

Сервер проверяет ID, валюту, целочисленную положительную цену, наличие, способы оплаты и HTTPS-ссылку. Затем ИИ проверяет внутренние противоречия между названием, описанием, ценой, наличием и способом оплаты и подготавливает краткое описание на узбекском языке. Проверяются все новые и изменённые записи; неизменившиеся записи используют сохранённый результат проверки с тем же отпечатком содержимого и моделью. Источник при этом опрашивается заново каждый час.

При отклонении, тайм-ауте или ошибке ИИ запись не публикуется: сохраняются старая информация и прежнее время проверки. В статусе появляются `pending_review`, `pendingReviews` и `aiErrors`; на следующем цикле выполняется повторная попытка. Изменение цены или способа оплаты всегда требует новой проверки. Для остальных успешно проверенных записей обновление продолжается.

Проверка ИИ означает анализ предоставленных сведений, **не независимое подтверждение цены или юридических возможностей продавца**. Модель не посещает ссылку и не узнаёт реальную цену без источника. При изменениях выполняются платные запросы выбранному ИИ-провайдеру. Персональные данные заказчиков не передаются.

Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Формат ответа проверяется сервером. ИИ не может менять цену, наличие и способы оплаты: эти поля сохраняются из фида.

## Приоритет B2B

Внутри карточки сначала идут предложения с `bank_transfer`, даже если цена выше. Внутри каждой группы — по возрастанию цены. Карточки товаров с такими предложениями также идут первыми, в том числе после фильтрации и в поисковых подсказках. Цена карточки и начальное значение калькулятора относятся к первому B2B-предложению. Оно помечается как оплата перечислением, а не как самое дешёвое.

Для обновлённого товара демонстрационные предложения исключаются из сравнения. Каталог может быть смешанным: часть товаров ещё демонстрационные (`demo` у товара, `mixed` у каталога). После появления реальных данных история показывает сохранённые цены приоритетного предложения с датами; это не обязательно минимальная рыночная цена.

Сайт получает сохранённый каталог при загрузке и раз в минуту, без вызовов ИИ из браузера и без изменения вёрстки/CSS. При ошибке остаётся последняя загруженная версия. Устаревшие предложения помечены в описании; публичный API заказа отклоняет устаревшие или недоступные предложения. Кнопка заказа на прежнем интерфейсе пока остаётся демонстрационной.

## Настройки и обслуживание

- `SYNC_INTERVAL_MINUTES=60`: интервал от начала одного цикла до следующего. Если цикл длится дольше интервала, новый запускается после завершения, без наложения.
- `SYNC_STALE_MINUTES=120`: срок, после которого предложение считается устаревшим.
- `PRODUCT_SOURCES_FILE`: путь к JSON-массиву источников, максимум 10.
- `OPENAI_API_KEY`, `OPENAI_MODEL`: обязательны для публикации новых данных.

Журнал `sync_runs` хранит последние 500 результатов; `live_price_history` — последние 500 точек на товар. Блокировка в SQLite защищает от одновременных циклов двух процессов. Ответы источников ограничены по размеру и времени; редиректы отключены. Конфигурация и ключи не раздаются HTTP-сервером. Для резервного копирования остановите сервер и скопируйте каталог `data`.
